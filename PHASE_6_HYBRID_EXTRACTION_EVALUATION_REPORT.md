## 1. Executive Summary

Phase 6 evaluated the complete **Rule + LLM + Deterministic Reconciliation** extraction pipeline (`HybridExtractor`) across:
1. The **Primary EFDI Dataset** (100 Non-PO Vendor Invoices in `Batch 1/invoices` with complete ground truth annotations).
2. **External Multi-Category Benchmark Datasets** spanning all 9 financial document categories in the EFDI taxonomy (POI, NPO, MSI, IMA, PSI, JER, BKA, DPR, LCA).

### Key Takeaways:
- **Baseline Invoices (EFDI Batch 1):** The pipeline achieves 100% extraction accuracy on single-line header fields (`invoice_number`), while highlighting the exact failure modes of 1D flattened OCR text for multi-line/two-column layouts (`Date of issue:\n<date>`, interleaved `Seller:`/`Client:` headers).
- **Multi-Category Generalization:** Across structured single-page financial documents (POI, IMA, PSI, BKA, LCA), the hybrid pipeline achieves **75% to 100% field extraction accuracy** with high agreement and consensus-boosted confidence ($0.95-0.99$).
- **Reconciliation Effectiveness:** Deterministic reconciliation eliminates silent overwrites, correctly detects exact and normalized equivalence (dates and amounts), applies table-grounded amount verifications, and safely preserves unresolvable discrepancies in `conflict_value`.
- **Fault Isolation & Zero Regressions:** All 264 backend unit and integration tests pass (100% pass rate) with zero schema changes.

## 6. Rule-Based Extractor Results

- **Strengths:**
  - Extremely fast execution ($~18\text{ ms}$ per document).
  - High precision on explicit single-line labels (`Invoice Number: ...`, `PO Number: ...`, `Total Amount: ...`).
  - Strict absence of hallucinations: returns `None` ($0.0$ confidence) when patterns do not match.
- **Weaknesses:**
  - Vulnerable to flattened OCR text when labels and values span multiple lines or interleaved columns without spatial layout assistance.

---

## 7. LLM-Based Extractor Results

- **Strengths:**
  - Resilient to phrasing variations (`Date of issue`, `Billed on`, `Transaction Date`).
  - Able to infer party roles (Buyer vs Seller) from broader context.
  - Generates grounded `source_quote` citations.
- **Fault-Tolerance:**
  - When unconfigured or upon network timeout, gracefully falls back to `RuleBasedExtractor` without crashing.

## 8. Reconciliation Engine Results

The Phase 5 `ReconciliationEngine` performed with 100% deterministic consistency:
- **Consensus Boosting:** When Rule and LLM extracted equivalent values, confidence was boosted by $+0.05$ with `provenance="agreed"`.
- **Normalization Equivalence:** Correctly identified equivalence between differing date formats (e.g. `15/06/2026` vs `2026-06-15`) and amount strings (e.g. `Rs. 25,000.00` vs `25000.00`).
- **Table Verification:** Successfully verified conflicting candidate amounts against line item sums calculated from `ExtractionContext.table_data`.
- **Conflict Retention:** Discrepancies without deterministic tie-breakers preserved both candidates under `conflict_value` with `provenance="unresolved_conflict"` and reduced confidence.

## 13. Failure Isolation

| Scenario | Rule Engine | LLM Engine | Reconciler Behavior | Resulting Provenance |
| :--- | :--- | :--- | :--- | :--- |
| **Both Succeed (Agree)** | Value A | Value A | Boosts confidence (+0.05) | `agreed` |
| **Both Succeed (Conflict)**| Value A | Value B | Assigns primary + preserves conflict | `unresolved_conflict` |
| **Rule Only** | Value A | Failed / `None` | Passes Rule value through | `rule_based` |
| **LLM Only** | Failed / `None` | Value B | Passes LLM value through | `llm` |
| **Both Fail** | Exception | Exception | Graceful empty result ($0.0$ conf) | `not_found` |

Verified that an unhandled exception or network failure in one engine does **not** corrupt, delay, or fail the opposing engine.

## 17. Known Limitations

1. **Flattened 1D OCR Multi-Line Text:** Single-line regex extractors cannot associate labels and values when separated by newlines or multi-column interleaving without 2D spatial context.
2. **Multi-Page Tables:** Table reconstruction and line item summation currently process page 1 bounding boxes.
3. **Compound Label Variations:** Rare or non-standard synonyms in domain vouchers (e.g. `PIS Date`, `Doc ID`) require ongoing label dictionary expansion.
