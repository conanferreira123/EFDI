Path 2: Local Development with Hot-Reload
Use this guide when you want to actively develop the project with live code reloading.
The backend and frontend run directly on your machine — no containers involved. For
a clean deployment on a new machine with no development intent, use the Docker
Compose guide instead.

Step 2 — Create the Database
Why: The backend connects to Postgres via DATABASE_URL . The database, user, and
password must exist before running migrations.
Inside the Postgres shell, run:
Why the schema grant: PostgreSQL 15 changed the default privilege model. Without it,
Alembic can connect to the database but cannot create tables, and migrations will fail with
a permission denied for schema public  error.
Verify the connection works:
efdi/
├── backend/
├── frontend/
├── docker-compose.yml   ← not used in this guide
├── .env                 ← docker-compose env, not used here
└── .env.example         ← root-level example, also not used here
bash
# Open a Postgres shell as the superuser
# Mac/Linux:
psql -U postgres
# If that errors on Linux, use:
sudo -u postgres psql
sql
CREATE DATABASE efdi;
CREATE USER efdi_user WITH PASSWORD 'efdi123';
GRANT ALL PRIVILEGES ON DATABASE efdi TO efdi_user;
-- PostgreSQL 15+ requires this additional grant:
\c efdi
GRANT ALL ON SCHEMA public TO efdi_user;
\q

=== PAGE 6 ===
Variable
Why this value
DATABASE_URL
Uses psycopg2  (sync driver) — matches what SQLAlchemy
and Alembic use in this project
APP_ENV=development
Required for seed_users.py  to run (it refuses if
APP_ENV=production ). Also relaxes the SECRET_KEY 32-
char minimum
OCR_DEFAULT_ENGINE=stub
Safe starting point — confirms the full pipeline works before
adding OCR model weights
CORS_ORIGINS
Vite proxies /api/*  to the backend, but the backend still
validates the Origin  header. Both localhost  and
127.0.0.1  are listed because browsers treat them as different
origins

Step 5 — Install Python Dependencies
Core packages (always required)
What this installs: FastAPI, Uvicorn, Gunicorn, SQLAlchemy, Alembic, psycopg2-binary,
Pydantic, python-jose (JWT), bcrypt, PyMuPDF, OpenCV, Pillow, scikit-learn, and all
pinned transitive dependencies.
OCR packages (required for real OCR, skip for stub)
If you set OCR_DEFAULT_ENGINE=stub  in Step 3, skip this section for now. Come back once
the app is running correctly.
For EasyOCR:
Why two steps for torch? The default PyPI torch  wheel dynamically links against
NVIDIA CUDA libraries ( libcudart.so , libcublasLt.so ). On a machine without an
NVIDIA GPU and drivers, import torch  crashes at load time — not at runtime — even
if you pass gpu=False . The CPU-only wheel from download.pytorch.org/whl/cpu
(~190 MB) has no CUDA dependency and imports cleanly on any machine. EasyOCR
requires torch, so this must be installed before EasyOCR will work. This is documented
in backend/requirements-ocr-torch-notes.txt .

Step 8 — Start the Backend
Why --reload : Uvicorn watches the app/  directory and automatically restarts the server
when you save a Python file. This is the hot-reload behaviour that makes manual setup
useful for development.
Why not Gunicorn here: Gunicorn's multi-worker mode doesn't support hot-reload. Use
Uvicorn directly for development.

Step 9 — Set Up and Start the Frontend
Open a second terminal (keep the backend running in the first one).
Why npm install  and not npm ci : npm ci  is for CI environments — it requires an exact
lockfile match and deletes node_modules  first. npm install  is the standard dev
command; it installs from package-lock.json  and is forgiving of minor environment
differences.

Troubleshooting
psycopg2  install fails on Mac (Apple Silicon)
The binary wheel ( psycopg2-binary ) in requirements.txt  handles ARM64 — it should
install without issues. If it fails:
alembic upgrade head  fails with relation "alembic_version" does not exist
This is normal on the very first run — Alembic creates that table itself. If the error is
something else, the most common cause is a wrong DATABASE_URL  in backend/.env .
Double-check the username, password, and database name match what you created in Step
2.
Backend starts but login returns 401 / JWT errors
Check that SECRET_KEY  in backend/.env  is not the literal placeholder value change-me-
to-a-long-random-string . The app validates this at startup and will log a clear error if it is.
Generate a real one:
Frontend shows a blank page or crashes on load
Check the browser console (F12) for specific error messages.
EasyOCR crashes on first OCR request
Most likely torch  is not installed or the CUDA-linked PyPI wheel was installed instead of
the CPU wheel. Verify:
If it errors, reinstall:
bash
brew install libpq
pip install psycopg2-binary --no-cache-dir
bash
openssl rand -hex 32
bash
cd efdi/frontend
npm run build   # run a production build to see TypeScript/compile errors clear
